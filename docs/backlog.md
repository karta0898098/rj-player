## 1. 幻覺 cue 的結構過濾（max_speech 撞頂 + 重疊 + 字元密度過低）

**狀態**：待處理
**發現於**：v0.2.0 實測（video `3cXUHPT2isw`，2026-07-24）

### 問題

Whisper 陷入幻覺迴圈時會吐出一批**特徵一致**的 cue，現有三層防線只擋得住
其中「文字剛好在清單上」的那些。實測 log：

```
[hallucinations] dropped 15/118 known-artifact cue(s)   ← 全靠文字比對
[energy_gate]    kept 103/103, dropped 0                ← 能量層完全沒表態
```

被砍的 15 句全是 `ご視聴ありがとうございました` / `ご清聴〜`，每句**剛好
29.98 秒**（撞 `asr.py` 的 `max_speech_duration_s = 30`），尾段大量重疊
（622.5 / 628.7 / 648.9 / 652.3 / 661.0 / 671.0 / 681.2 / 684.1s）。

**漏網的實例**（同一支影片，留在最終 `subtitles.json` 裡）：

```
30.0s @391.1s  「はぁー」      ← 30 秒、3 個字
396.9-397.9s   「あーで」      ← 與上一句重疊
```

### 為什麼三層都漏掉

| 防線 | 為何無效 |
|---|---|
| `hallucinations.py` blocklist | 文字不在清單上（「はぁー」不是罐頭語，也**不該**加進清單——它有合法的歌詞讀法） |
| `energy_gate` drop | 該區間有人聲能量，peak 過門檻，正確地保留 |
| `energy_gate` trim | 只裁尾部靜音；這句整段都有能量 |
| `polish` LLM 留空 | 有機會抓到，但當次沒有（LLM 判斷保守，且單看文字「はぁー」像是合法的嘆息） |

也就是說：**文字層和能量層都失效時，還有第三個正交訊號沒被使用——結構。**

### 建議作法

這批幻覺有一個與文字內容、與音量都無關的指紋：

1. 長度**剛好等於 `max_speech_duration_s`**（Whisper 從頭到尾找不到自然
   斷點才會撞頂，正常語句不會）
2. 與相鄰 cue **重疊**
3. **字元密度極低**（「はぁー」＝ 3 字撐 30 秒；真人不會用 30 秒唱/說 3
   個字還不換氣）

單一條件都會誤判（拖音本來就可能長且字少），但**三者同時成立**幾乎不可能
是真內容。建議以合取（AND）為預設，並把門檻寫成具名常數方便調。

**實作位置**：新增 `ai/pipeline/` 下的結構過濾，或併入 `energy_gate` 的
同一趟掃描（它已經有 cue 列表與時間資訊，不需要音檔）。若不依賴音訊，放
`hallucinations.py` 也合理——那樣**原始混音路徑也能受惠**（跟 blocklist
同樣的理由），優先考慮這個位置。

**注意**：需要知道當次的 `max_speech_duration_s`（分離路徑 30、未分離
15、使用者可覆寫），要從 `asr` 那邊傳進來而不是寫死。

### 驗收標準

- 上述「はぁー」案例被砍掉，同一支影片其餘 102 句不受影響
- 合成測試涵蓋反向案例：**長拖音（`ああああ` 撐 20 秒但未撞頂）不可被誤
  砍**——這是最重要的負向保證
- 一句撞頂但字很多、且不重疊的 cue 不可被砍
- 沿用既有的 log 契約：被砍的每一句都要有一行 log 說明命中哪個條件
- `VOCAL_ENERGY_GATE=off`（或等價開關）要能一併關掉

## 2. Windows 端 Demucs 路徑實測

**狀態**：待處理（需要 Windows 機器，開發者只有 mac）

v0.2.0 新增的 `install_demucs_deps`（Doctor fix）與 `separate.py` 的
torch/torchaudio 使用在 Windows 上**完全未經驗證**。已知風險：

- `requirements-demucs.txt` 在 Windows 的 torch wheel 解析（CPU vs CUDA
  變體）
- torch hub 模型快取路徑（`~/.cache/torch` 在 Windows 的對應位置）與
  `HF_HOME` 的處理方式不同
- `separate.py` 已避開 `torchaudio.load`（改用 stdlib `wave`），所以
  TorchCodec 缺件問題不該重現，但需實測確認

發版後請優先在 Windows 跑一次「乾淨機器 → Doctor 安裝 demucs → 音樂影片
產生字幕」的完整路徑。
